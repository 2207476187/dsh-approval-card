# 0002 用本地补丁脚本修审批门的路径截断

- 状态：Accepted
- 日期：2026-11-04

## 背景

`dsh-approval-gate` 判断「这次操作动的是工作区内还是外」时，把 `edit`/`write` 的
`file_path` 也交给 `extractAbsolutePaths()`。那是一个**文本**提取器（词法遇空白即停），
于是工作区路径 `D:\DeepSeek Harness工作目录\DeepSeek\docs\devlog\2026-11.md` 被截成
`D:\DeepSeek`；它不在工作区之下，判成「工作区外」→ 每次改工作区内文件都转人工审批。

取证：`auto-approve\events.jsonl` 的事件里 `files` 是完整路径，而 `targets` 是
`["D:\\DeepSeek"]`、`targetScope: "outside"`；直接调官方模块复现
`extractAbsolutePaths(完整路径)` → `D:\DeepSeek`，而 `classifyPathScope([完整路径])` → `inside`。

## 候选

1. **配置绕开**：把门配置 `outsideNeedsHuman` 设为 `false`（持久化在 `auto-approve\allowlist.json`，更新不会被覆盖）。
   但这会把「真的写工作区外」也一并不再转人工，安全姿态整体下调，只为绕开一个字符串解析 bug 付出太多。
2. **把工作区移到无空格路径**。会话目录名按路径编码、`AGENTS.md` 与多处文档引用全要改，风险最大。
3. **改门的 `resolveToolCallTargets()`**：结构化字段直接当一条路径，命令类字段仍走文本提取。改的是第三方包，
   `pnpm install` / 更新会覆盖。
4. 向上游提 PR 后等待。周期不可控，而问题每次写文件都在发生。

## 决定

选 3，并把「怎么重放」一起做成资产：`tools/patch-approval-gate.mjs`。

- 只改一个函数，不动裁决顺序、不动任何判定逻辑；锚点不唯一就放弃（宁可没修，不能改错位置）。
- 幂等：已打补丁则直接退出；写入前备份 `src/index.mjs.bak-targets-<时间戳>`；写完 `node --check`，失败回滚。
- 更新依赖后重跑一次即可（`--status` 只看状态，`--dry-run` 只看会改什么）。
- 同时保留一个更便宜的旁路：真到了补丁没重放、又被反复打断的场合，可以临时把
  `outsideNeedsHuman` 设成 `false` 应急，但那是**降低安全姿态**的手段，不作为常态。

## 代价

- 每次更新 `dsh-approval-gate` 后都要重跑补丁；忘了就退回旧行为（表现是又开始频繁弹卡，不会静默出错）。
- 本地补丁在 diff 上与上游分叉，上游修好之后要记得回头删掉这个脚本并重装依赖。
- 该函数的 `targets` 语义从「文本里提取出的绝对路径」变成「文本提取 + 结构化整条」，审计记录里
  同一路径可能出现两条（`raw` 相同、`path` 相同，已被 `seen` 去重，实测为 1 条）。
