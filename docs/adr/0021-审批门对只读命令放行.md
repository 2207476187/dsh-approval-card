# 0021 审批门对只读命令放行

- 状态：已采纳（2026-11-24）
- 相关：`plugins/dsh-hooks-shim/rules/gate-bridge.mjs`、`tools/gate-readonly-allow.mjs`、`tools/verify-gate-readonly.ps1`

## 背景

审批门的 R1 规则只做一件事：把命令文本里的绝对路径抽出来，凡是落在工作区外就 `ask`。它不区分这条路径被读还是被写 —— 因为判据是字符串，不是行为。

后果是读数占了绝大部分打扰。当前这场会话被统计的 656 条审批事件里，绝大多数 reason 是「目标含工作区外路径」，而对应动作是 `Get-Content`、`Select-String`、`Get-ChildItem`、`Get-FileHash` 这类纯读；真正的写只有个位数。查一行宿主源码要点一次卡，这件事每天都在发生。

同一套判据在另一个方向上是漏的：把路径放进变量（`$ai = '...'`）再使用，字符串扫描抓不到。所以它既挡了效率，也没真正挡住意图 —— 挡住的是「把手写进命令」这种最笨的写法。

## 候选

- **A 保持现状**：规则简单、行为可预期。代价是只读排查持续被拦，人容易形成「无脑点允许」的肌肉记忆 —— 那会让审批门整体失效。
- **B 只读命令放行**：在 R1 之前加一层 R0，纯只读的 exec 命令即使引用工作区外路径也不问。凭据、破坏性动作、网络外发仍按原规则拦。
- **C 按目录放开读**：白名单几个常用目录（宿主包目录、profile 目录）。代价是每加一个目录都要改配置，且「目录可读」与「命令只读」是两个维度，组合起来仍然会误放写操作。
- **D 彻底关掉 R1 的文本扫描**：只按目标路径判，不看命令正文。这样读不拦、写也不拦（除非路径在字段里），等于拆掉规则。

## 决定

选 **B**。

实现落在 `gate-bridge.mjs`：

1. `READ_CMDS` —— 只读命令白名单（`Get-Content`/`gc`/`type`/`cat`/`Select-String`/`sls`/`grep`/`rg`/`Get-ChildItem`/`gci`/`ls`/`dir`/`Get-Item`/`Get-FileHash`/`Test-Path`/`Resolve-Path`/`Get-Command`/`Get-Member`/`Get-Process`/`Measure-Object`/`Select-Object`/`Sort-Object`/`Format-Table`/`Out-String`/`ConvertFrom-Json`/`Compare-Object`/`diff` 等）。
2. `WRITE_VERBS` —— 全文出现任一写动词（`Set-`/`Add-`/`Remove-`/`New-`/`Clear-`/`Move-`/`Copy-`/`Rename-`/`Out-`/`Invoke-`/`Start-`/`Stop-`/`Write-`/`Save-`/`Export-`/`Import-`/`Install-`/`Update-`/`Tee-`/`ConvertTo-SecureString-` 等）即判「不是纯读」。用来兜住括号嵌套这类分段白名单看不见的形态。
3. `NOT_PURE_READ` —— 重定向（`>`/`>>`/`<`）、子表达式 `$( ... )`、反引号、`& $var`、`Invoke-Expression`/`iex`、`Start-Process`/`Start-Job`、`ForEach-Object`、`| %`。
4. 分段校验：把命令按 `;`、`&&`、`||`、`|` 切开（先挖掉引号内容以免切错），每段首个 token 都必须在 `READ_CMDS` 里。

放行条件（全部满足）：工具是 exec 类、`outside` 非空、**且 `reasons` 只有「工作区外路径」这一条**、且命令通过上面的只读判定。也就是说 R2（破坏性）、R3（凭据）、R4（外发）只要有任何命中，R0 不成立，照旧弹卡。

选择「白名单 + 多重排除」而不是「黑名单 + 补漏」的理由：漏放的代价是多弹一次卡，误放的代价是一次静默写入。白名单写错只会打扰，黑名单写错会放行。

## 代价

- `READ_CMDS` 是手工清单，新工具（或新别名）要手动补；漏补的表现是「仍然弹卡」，不是静默放行。
- 保守到会误拦一些只读组合：`Import-Csv`（带 `Import-`）、`Get-Content ... | ForEach-Object { ... }`、`git log`（`git` 未入白名单）、`node xxx.mjs`（能执行任意代码，故意不放）。
- 已知缺口：`node -e` / `python -c` 这类「命令名只读、参数是代码」的形态，R0 判不了（首 token 不在白名单所以不误放，但 R2 也不含它们，最终是 `none`）。这一层靠 DSH 的沙箱围栏兜底，gate 本身管不住。
- 路径拼进变量仍然能绕过 R1（这个问题 R0 没有改变，也没有恶化）。
- 只读的跨区访问在 gate 层放行后，`read` 工具那条路仍然由文件围栏（purge `#16` 已还原）判，两者是不同机制，不要混为一谈。
