# 0025 升级后如何把 purge 与审批门恢复成现在这套状态

- 状态：已采纳
- 日期：2026-11-24

## 背景

这两天把 purge 的大量行为改了回来，最终稳定在 `22 applied / 47 skipped / 16 na / 1 missing_file`，宿主侧还有一批定点回改（`#33`/`#48`/`#55`/`#72`/`#89`/`#38`/`#39`/`#59`/`#78` 等）。同时自己写的审批门插件 `dsh-hooks-shim` 也改过两次（不再扫文档正文、只读命令放行）。

问题在于这些改动都活在 `~/.dsh` 与 `X:\Program Files\...\resources\app` 下，**都不在版本控制里**：

- `dsh-purge/lib/core.js` 有 47 处停用桩、两处 `disabled` 短路、`#1` 的重放规则、`#42` 的原子写加固；
- `@deepseek-ai/*` 下九个宿主文件被定点回改；
- `dsh-hooks-shim` 整个插件只有一份，改完就没有历史。

DSH 每次升级会把 `resources\app` 换成官方原版，purge 自己升级/重装会把 `core.js` 换掉。结果是：**点一次「应用」，47 条被停用的补丁全部重新打上，刚修好的宿主文件重新变脏。**

所以要回答的是：升级之后靠什么把状态弄回来，而且怎么保证不会再手滑打回去。

## 候选

**A. 保持手工**：照 `tools/README.md` 里那串命令一条条敲。

- 优点：零新增代码。
- 缺点：现在是七步、二十一条 id，还夹着三个「默认预览、要 `--apply`」的脚本和四个「默认写盘、要 `--dry-run`」的脚本。顺序和参数记错一次就是半小时的排查；漏跑 `purge-skip-disabled.mjs` 会让下一次点应用直接毁掉前面全部工作。已经手滑过一次（`.build` 里的失败记录）。

**B. 把 `core.js` 与宿主文件快照进仓库，升级后整份覆盖回去**：

- 优点：一步到位，不需要理解补丁。
- 缺点：`core.js` 是 purge 本体（348 KB），覆盖回去等于把 purge 也退回到今天的版本，新版补丁与新代码一起丢失；宿主文件同理，会把官方修好的东西带回旧版。快照没有语义、无法审阅，而且每次改动都要重新提交几百 KB。

**C. 脚本重放 + 自建插件源码入库**（采纳）：

- 新增 `tools/purge-restore-state.mjs`，把七步固定成顺序，自动补 `--apply`/`--dry-run`，逐步报错即停。
- 把 `dsh-hooks-shim` 整个插件镜像到 `plugins/dsh-hooks-shim/`（排除 `.bak-*`，`.gitignore` 已有规则）。
- 宿主与 purge 的改动仍靠各自的定点脚本重放，不存快照。

**D. 只把插件入库，purge 继续手抄**：半套，`core.js` 依旧无保护，否。

## 决定

采用 C：

1. `tools/purge-restore-state.mjs` —— 一条命令，七步顺序固定；默认演练，`--apply` 才写盘。跑完提示重启并核对 `22/47/16/1`。
2. `plugins/dsh-hooks-shim/` —— 十个源码文件入库（`rules/gate-bridge.mjs`、`src/index.mjs`、`test/selftest.mjs`、`install-hooks-shim.ps1`、`hooks.json`、`cordis.patch.yml`、`package.json`、README、报告、`rules/tap.mjs`）。
3. `tools/README.md` 的「更新 DSH 之后」把手工两条命令换成这一条，并写清为什么前三条必须在第四条之前。

判据：脚本对**已经恢复好的状态**必须全程报「已是官方原文 / 无需改动」——这就是幂等性的现场证明，已在演练里跑过一次。

## 代价

- **脚本靠字面量活着**：`STRING_FIXES`、锚点、官方片段都按今天的文案写死。上游改一个词，脚本就报「未匹配到已知污点」并 `exit 3`——这是故意的（宁可停下也不猜），代价是升级后可能要人工补一条。
- **停用清单是编号**：`6 15 16 22 23 …` 共 21 个。purge 新版若重新编号，同一编号指的可能是另一条补丁，脚本会照打不误。升级后必须用 `node .build/check-patch-status.mjs <id…>` 核对名字，不能只看状态。
- **插件入库带来第二个真相源**：仓库里的 `plugins/dsh-hooks-shim/` 与 `~/.dsh` 里运行的那份会分叉。改完必须回同步，目前没有自动机制，靠提交前 `Get-FileHash` 比对。
- **仍要人工点一次「应用」**：脚本只保证「应用」不会打回停用项，不会替你去点。面板计数对不上时，责任仍在跑脚本的人。
