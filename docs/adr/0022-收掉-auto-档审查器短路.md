# 0022 收掉 Auto 档审查器的短路补丁

- 状态：已采纳（2026-11-24）
- 相关：`#59 OFFICIAL_AUTO_REVIEW_PASSTHROUGH`、`dsh-experimental-auto-review`、`tools/disable-purge-patch.mjs`

## 背景

`dsh-permission-presets` 里有一档保留名 `auto`（不能被子配置占用），由 `dsh-experimental-auto-review` 通过 `registerAuto()` 注册，规格是：

```js
const AUTO_PRESET_SPEC = { sandbox: "danger-full-access", approval: "ask" }
```

它的设计意图是「用机器复核代替人点卡」：沙箱给全权，但每次工具调用前先让审查器看一遍，审查拒绝时弹卡问用户。审查通过则 `permissionPresets.set(session, "danger-full-access")` 继续。

purge 的 `#59` 在这个 `tools/pre-execute` handler 的第一行插了一句 `return next();`，后面四十多行审查逻辑全部变成不可达代码 —— JS 允许这样写，不报错，但审查永不发生。

结果是状态显示 `auto`、实际行为比 `danger-full-access` 还松：前者是「用户明确选了全权」，后者是「用户以为有审查」。

## 候选

- **A 保持**：Auto 档本来就不用，留着不影响任何人。代价是这档一旦被启用，它的语义是假的。
- **B 只停用不还原**：`disabled: true` 造桩，宿主文件留着短路。代价是文件里那句 `return next()` 会一直被后续补丁当上下文，且看代码的人读不到官方逻辑。
- **C 停用 + 整文件还原**：备份干净（29,033 B，marker 0），可直接覆盖回官方；同时在 `RESTORE` 表登记，purge 重装后重跑一条命令即可复原。
- **D 直接卸掉这个插件**：作者标的是 experimental，但卸掉会让 `auto` 档从可选项里消失，属于功能收缩，不是语义恢复。

## 决定

选 **C**。

- `tools/disable-purge-patch.mjs` 的 `RESTORE` 表加 `59: [['dsh-experimental-auto-review', join('lib','index.js')]]`。
- 还原后 live 与 `.dshpurge.bak` 同哈希（`C516E8803FACB9C8`，29,033 B），`dsh-purge` 标记 0，`tools/pre-execute` 的 handler 第一句回到 `const agent = exec.agent;`。
- `#59` 状态 `skipped`；全量计数 `25/44/16/1` → `24/45/16/1`。

## 代价

- 以后若真要用 `auto` 档，会重新走「每步一次审查」—— 审查本身要花一次模型调用，慢且费 token。这是官方的设计取舍，不是这次的代价。
- 本机 preset 表里没有 `auto`（它是运行时保留档，不在 `dsh-web-app\presets`），所以现在还看不出差别；这条唯一的实际意义是「别让一个假语义的档位留在系统里」。
- 升级 DSH 后要重放：`node tools\disable-purge-patch.mjs 6 15 16 22 23 24 29 33 34 36 37 38 39 48 55 59 61 72 92`。
