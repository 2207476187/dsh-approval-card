生成时间：2026-10-18

## 1. 为什么必须有这一层

升级到 0.2.1-rc.2 后，宿主里这 11 个包**消失**：

```
dsh-client-store          dsh-client-ui-primitives   dsh-client-ui-slots
dsh-experimental-schedule-bundle                     dsh-hook-protocol
dsh-hooks-claude-code     dsh-hooks-codex            dsh-invariants
dsh-subagent-in-process-driver                       dsh-webhook
dsh-webhook-github
```

其中 `dsh-hooks-claude-code` 是宿主里**唯一**把 `tools/pre-execute` 瀑布的返回值
翻译成 `{kind:'deny'}` / `{kind:'ask'}` 的插件。断了它，链路就断在这里：

```
工具要执行
   ↓  dsh-tools::prepareExecution
   ↓  ctx.waterfall(carrier, "tools/pre-execute", exec, () => ({kind:"allow"}))
   ↓  ← 需要有人返回 {kind:"ask"}       ★ 新版这里没人回答了
   ↓  serviceAsk() → approval.request()
   ↓  dsh-approval-gate 的 ctx.on('approval/request')
   ↓  弹卡
```

`dsh-approval-gate` 挂的是 `approval/request`，它**不碰** `tools/pre-execute`
（该字符串在 `src/index.mjs` 里出现 0 次）。所以门本身还在，只是上游没人递话了。

→ 本插件补的就是「有人返回 `ask`」这一环，判定仍然全部交给原门。

## 3. gate-bridge.mjs 的判定逻辑

四条判据，任一命中就 `ask`：

| 判据 | 触发条件 | 例 |
|---|---|---|
| R1 工作区外路径 | `PATH_KEYS` 字段整段值 或 command 里解析出的绝对路径，落在 workspace 之外 | `New-Item D:\__probe` |
| R2 破坏性动作 | 19 条正则：`rm -rf`、`Remove-Item -Recurse`、`rmdir /s`、`del /s`、`format`、`mkfs`、`dd of=/dev/`、`shutdown`、`diskpart`、`vssadmin delete`、`bcdedit`、`reg delete`、`git push --force`、`git reset --hard`、`npm publish` … | `Remove-Item -Recurse -Force D:\x` |
| R3 凭据 | 13 条正则：`.ssh/`、`.aws/`、`.dsh/.credentials`、`credentials.yaml`、`id_rsa`、`id_ed25519`、`.env`、`security_token`、`.npmrc`、`.pypirc`、`netrc`、`login data` … | `Get-Content .ssh\id_rsa` |
| R4 网络外发 | 仅当工具名匹配 `pwsh\|powershell\|bash\|sh\|zsh\|shell\|exec\|run\|terminal\|cmd` 才查；11 条正则：`curl`、`wget`、`Invoke-WebRequest`、`Invoke-RestMethod`、`nc -`、`scp`、`sftp`、`rsync`、`ssh user@`、`fetch(`、`axios` | `curl -X POST https://…` |

升级为 `deny` 的唯一情形：**破坏性 + 工作区外 + 目标是系统目录或盘符根**
（`[a-z]:\?(windows|program files|program files (x86))`、`c:\`、`d:\`、`[a-z]:\`）。

只读工具白名单（直接放行，不打扰）：`read`、`read_file`、`readfile`、`glob`、`grep`、
`list`、`ls`、`list_dir`、`listdir`、`todo_write`、`todowrite`、`todoread`、
`web_search`、`websearch`、`web_fetch`、`webfetch`、`get_text`。

**失败策略：一律 open。** stdin 读不了、payload 坏、判定器内部抛异常、10 秒没收到 EOF —
全部 `exit 0`（无意见），绝不因为桥接器自己出问题而阻断会话。

## 5. 修过的三个 bug（都是同一个主题：空格）

路径里带空格是本机常态（工作区就叫 `DeepSeek Harness工作目录`），
三处都栽在「按空白切分路径」上：

| 轮次 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `D:\DeepSeek Harness工作目录\…\test.txt` → `D:\DeepSeek` | `extractAbsolutePaths` 用 `[^\s]` 截断 | 先按引号切，引号内整段当一个路径 |
| 2 | `C:\…\下载\报告 v2.txt` → `C:\…\下载\报告` | `flattenInput` 把路径字段拼进自由文本，引号信息已丢 | 路径字段不进自由文本，改由 `collectFieldPaths()` 整段取 |
| 3 | 引号内 `"D:\…\WorkBuddy Ai"` 仍被切成 `D:\DeepSeek` | 整段登记后又按空格切了一遍 | 引号内容本身是绝对路径时**只登记整段，绝不切** |

**教训一句话：路径字段整段取，只有 command 这类自由文本才做切分。**

> 顺带说明：审批门自己的 `paths.mjs` 有同一个 bug（含空格路径被截断），
> 这次没动它 —— 它现在是唯一没被 purge 改过的干净模块，改它等于引入自定义补丁。

## 7. 升级到 0.2.1-rc.2 之后的收尾

升级完成后 **两件事必做**：

1. **确认 shim 还在**
   升级会重写 `resources\app`，但**不会动** `%DSH_HOME%\profiles\`。
   所以插件本体和 `cordis.patch.yml` 都会保留。
   但 profile 的 `node_modules` 可能被 pnpm 重新解析 → 重启后先跑一次
   `install-hooks-shim.ps1 -VerifyOnly` 看 `插件已复制 yes` / `cordis.patch 已插入 yes`。

2. **确认 purge 的重打行为**
   `cordis.patch.yml:139` 是 `autoApplyOnStart: false`，
   所以升级后 purge **不会**自动重打 82 条补丁；需要手动点「应用」。
   在那之前，审批门链上的 7 个文件保持官方原样（安全状态）。

## 9. 边界（这层不解决什么）

- **不做最终判定**。批不批仍然是 `dsh-approval-gate` 的事，这里只负责「把话说出去」。
- **不覆盖 hooks 全部语义**。`SubagentStart`/`SubagentStop` 只做记录不做拦截；
  官方 `agent/turn-stopping` 的 steer 行为完整保留。
- **不认识动态路径**。`$env:TEMP`、变量拼接出来的路径、运行时才算出的路径，静态看不出。
  这类只能靠审批门自己那套「先沙箱拦、再问人」兜底。
- **不是安全边界**。它能被禁用、被改规则、被绕过 —— 它是保底，不是防线。
  真正的防线仍是沙箱（`workspace-write`）与审批门本身。
